# Executed agreement PDF — 2026-09-15

The PDF published after signing was an evidence summary: it listed document digests, field ink references, recipients, and the audit proof, and it inlined Markdown as plain Courier text. Uploaded PDFs appeared only as a digest, drawn signatures only as `sig:sha256:` references, and field geometry only as a line of coordinates. What a counterparty received was therefore a description of an agreement, never the agreement they signed. That is the production-readiness blocker this note resolves.

## Decision

The completion artifact's PDF is the **executed agreement**: the immutable sent document set, in document order, with every signed value drawn at the geometry frozen when the envelope was sent. The evidence summary is kept verbatim and appended as the final pages of the same artifact, so no evidence is lost and no second download is introduced.

- **Base pages are the sent bytes.** Uploaded PDFs are imported page-for-page from the original, re-verified against the size and SHA-256 pinned in `document-set.json`; Markdown uses the existing deterministic per-document rendering. Both are re-derived from the already-verified pinned revision rather than from a second, unverified pointer read.
- **Composition is in-house and Workers-compatible.** `pdf-object-reader.ts` (extracted from the uploaded-PDF metadata parser, so uploads and executed output share one bounded parser) walks the source object graph; `pdf-composer.ts` copies each page's subgraph with its filters intact and appends one overlay content stream per page. No Node-only runtime and no new dependency: `fflate` and the bundled subsetted font already ship.
- **Overlays are drawn in display space.** Field geometry is a unit square measured from the top-left of the page _as a reader sees it_, which is what the signing UI captured. The composer converts that into page user space, undoing `/Rotate` and a non-zero MediaBox origin, so a field placed over a rotated page lands where the signer put it.
- **Drawn signatures are composited from verified assets.** The PNG is read from its recipient-scoped content-addressed key, re-hashed against the `sig:sha256:` reference in the field value, decoded by a bounded decoder, and embedded as an image XObject with an `/SMask` so the transparent background does not paint over the agreement. Typed signatures, names, dates, and text are drawn in the bundled Unicode font (CJK included); checkboxes are drawn as a stroked path, needing no glyph.
- **Geometry is integrity-critical.** A signed value whose placement row is missing, incomplete, not scoped to a document in the sent set, out of range, or pointing past the document's pinned page count fails the publication closed. So does a missing or mismatched signature asset, and a base document that no longer paginates the way its document set pinned. There is no null-geometry fallback and no silently skipped field: an "executed" agreement with a missing signature is worse than one that is not published.
- **Nothing that can act is copied.** `/Annots`, `/AA`, and the source catalog are dropped; only static page content (`/Contents`, `/Resources`, `/MediaBox`, `/Rotate`, `/Group`) crosses into the artifact. The reader still refuses encrypted files and catalog-level `/OpenAction`, JavaScript, or embedded files.
- **Determinism is preserved.** No timestamps, no document ID, fixed deflate level, fixed field draw order, fixed object numbering. Identical evidence composes to identical bytes, so the artifact stays content-addressed and a replayed publication is a no-op.
- **Bounds everywhere.** Documents (20), fields (200), pages (800), input bytes (32 MiB), copied stream bytes (48 MiB), output bytes (32 MiB), objects (50 000), overlay operations (4 000), image dimensions (4096 px) and pixels (4 M), plus the parser's existing inflate, xref-chain, page-tree, nesting, node and token budgets. A breach is a non-retryable `completion_artifact_evidence_too_large`, not a runaway worker.
- **Legacy envelopes keep the evidence summary.** Envelopes sent before per-document publication have path-scoped fields with no frozen geometry, so there is nothing to execute against. Their PDF artifact stays the evidence summary, and the published PDF manifest says so explicitly: `signkit-completion-pdf-manifest-v2` records `artifactKind` (`executed-agreement-v1` or `evidence-summary-v1`), the page count, the appendix's first page, each document's page range, and each field's full frozen geometry.

Drawn signature uploads are now decoded at signing time, not just sniffed for the PNG magic bytes. An asset the compositor could not later decode would otherwise strand that envelope's completion artifact after the signature was already legally given.

## Consequences

- A completed envelope whose evidence cannot be executed faithfully publishes nothing at all — not even the JSON/Markdown manifest — until an operator resolves the integrity failure. That is deliberate: the alternative is publishing evidence that points at an agreement the system admits it cannot reproduce.
- The artifact is now as large as the documents themselves, where before it was always a few kilobytes of text. Envelopes near the 20-document, 20 MiB-per-upload ceilings can exceed the composition budget and fail closed; raising those ceilings means raising the composition bounds with them.
- Annotation-only content in an uploaded original (a form-field widget appearance, a sticky note) is not carried into the executed PDF. Flattening annotations safely is deferred rather than risking active content in the legal artifact.
- Cryptographic certification and sealing (PAdES) remain backlog. This artifact is a visual executed agreement plus a hash-chained evidence appendix, and must not be described as a certified or sealed PDF.
